1) Architecture (high level)

Implement a streaming, queue-backed extraction pipeline:

Upload → Create Job → Worker: OCR/Parse → LLM JSON extract → Normalize/Validate/Dedupe → Human Review UI → Commit to DB.

Scalable pieces:
	•	Storage: use existing abstraction; otherwise add S3-compatible driver later (start with local /storage/uploads).
	•	Queue: bullmq + Redis (use Upstash Redis URL if defined; else in-memory fallback for dev).
	•	OCR/Parsing:
	•	PDFs with text: pdf-parse or pdfjs-dist.
	•	Scanned PDFs/images: tesseract.js (per page) with auto-rotate; fallback to “send image page to LLM with vision” if OCR fails.
	•	LLM: OpenAI JSON-structured output for deterministic extraction.
	•	Validation: zod schemas; normalize dates/addresses; fuzzy-match entities/people to avoid duplicates.
	•	Human-in-the-loop: show a Review & Apply screen with diffs, confidence, and per-field accept/override.
	•	Observability: job status, durations, token usage; log PII safely.
	•	Security: authz on all endpoints, file type/size limits, virus scan stub (hook), PII-at-rest encryption option.

5) Worker pipeline (BullMQ)

Queue name: ingestion
Job ingestion:extract steps:
	1.	Load file from storage.
	2.	Parse text:
	•	If PDF has text layer → pdf-parse.
	•	Else if image/scanned → run tesseract.js per page (detect rotation).
If OCR fails, fallback: call OpenAI Vision (image input) for a page or two.
	3.	LLM extraction:
	•	Call OpenAI with structured JSON output (function-call / JSON schema).
	•	Model: a cost-efficient JSON-capable model (e.g., gpt-4o-mini or your project’s default).
	•	Send system prompt (below) + the flattened text (paged; chunk if very large; merge).
	4.	Validate/Normalize with zod:
	•	Normalize dates (date-fns parse heuristics).
	•	Title-case names, uppercase postal codes, strip punctuation.
	5.	Deduplicate/Match:
	•	Compare against existing org/people by name+number and string similarity.
	•	Return matches: {candidateId, score} so UI can link or create new.
	6.	Produce result:
	•	{ extraction: ExtractionResult, matches, warnings } and store to a temporary table or JSON blob keyed by jobId.

OpenAI extraction call (Node):

import OpenAI from "openai";
const client = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

// Use JSON schema (responses API) if available; otherwise function-calling.
const schema = {
  type: "object",
  properties: {
    organization: {
      type: "object",
      properties: {
        legalName: { type: "string" },
        number: { type: "string" },
        jurisdiction: { type: "string" },
        formationDate: { type: "string" },
        registeredOffice: { type: "string" },
        recordsOffice: { type: "string" }
      },
      additionalProperties: false
    },
    people: {
      type: "array",
      items: {
        type: "object",
        properties: {
          fullName: { type: "string" },
          firstName: { type: "string" },
          lastName: { type: "string" },
          address: { type: "string" },
          city: { type: "string" },
          province: { type: "string" },
          country: { type: "string" },
          postalCode: { type: "string" },
          email: { type: "string" },
          isDirector: { type: "boolean" },
          isOfficer: { type: "boolean" },
          officerTitle: { type: "string" },
          isShareholder: { type: "boolean" },
          shareClass: { type: "string" },
          shareSeries: { type: "string" },
          shares: { type: "number" },
          issueDate: { type: "string" }
        },
        required: ["fullName"],
        additionalProperties: false
      }
    },
    shareholders: { type: "array", items: { $ref: "#/properties/people/items" } },
    confidence: { type: "number" },
    confidences: { type: "object", additionalProperties: { type: "number" } },
    sourceMeta: {
      type: "object",
      properties: { filename: { type: "string" }, pages: { type: "number" } },
      required: ["filename", "pages"]
    }
  },
  required: ["organization", "people", "shareholders", "confidence", "sourceMeta"],
  additionalProperties: false
};

const system = `
You extract clean, normalized corporate registry data from PDFs (minute books, registers, share certificates).
Return only JSON conforming to the provided schema. Do not invent data.
For dates, output ISO (YYYY-MM-DD) if a complete date exists; else omit the field.
Set role flags: isDirector/isOfficer/isShareholder. officerTitle if present.
Map share details: class, series, shares (number), issueDate (ISO).
Extract addresses as single lines when possible; put city/province/postalCode separately if explicitly present.
Include per-field confidences between 0 and 1.
`;

const user = `
Document text (first 60k chars): 
--- BEGIN ---
${text.slice(0, 60000)}
--- END ---
If content exceeds limit, we may call you again with the rest.
`;

// If using Responses API with JSON schema:
const response = await client.responses.create({
  model: "gpt-4o-mini", // or your standard model
  input: [
    { role: "system", content: system },
    { role: "user", content: user }
  ],
  response_format: { type: "json_schema", json_schema: { name: "ExtractionResult", schema, strict: true } }
});
const json = JSON.parse(response.output_text);

(If Responses API isn’t available, use Chat Completions with tools/function-calling and enforce JSON parsing.)
